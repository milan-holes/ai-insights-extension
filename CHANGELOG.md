# Changelog

All notable changes to the AI Insights extension will be documented in this file.

## [0.1.12] - 2026-07-05

- **New: custom session folders for every provider, not just Claude Code** - `aiInsights.providers.claudeCode.additionalSessionPaths` previously only existed for Claude Code; it now has a sibling setting for every provider (`aiInsights.providers.copilot.additionalSessionPaths`, `...antigravity...`, `...codex...`, `...jetbrainsAI...`, `...visualStudio...`), so a non-standard storage location (moved home directory, synced backup, remote mount, `CODEX_HOME` override, etc.) can be added for any of the six providers, not only Claude Code. Each new setting is a `~`-expanding array of directories, editable from the new Settings panel's all-settings table (see the entry below) alongside every other setting. Antigravity's version is the odd one out: since its sessions live across two correlated directories (`brain/` + `conversations/`) rather than one flat folder, each additional path there is a home-style root expected to contain its own `brain/`/`conversations/` subfolders, mirroring `~/.gemini/antigravity/`. Implementing this surfaced and fixed a latent bug where a session discovered under a second Antigravity root could have its workspace/title incorrectly resolved from the _default_ root's metadata instead of its own (conversation IDs aren't guaranteed unique across roots) - fixed by deriving each file's metadata directory from its own path instead of a fixed instance field.
- **Changed: "Diagnostics" panel renamed to "Settings" and reworked** - the nav tab (now last in the nav bar instead of second-to-last) and panel title read "Settings" instead of "Diagnostics". The page now shows, top to bottom: the existing info tiles (Extension/VS Code/Platform/Node - unchanged), a new **"⚙️ All Extension Settings"** section listing every `aiInsights.*` setting from `package.json`'s configuration schema with its live value and an inline editable control (checkbox, dropdown, number, text, or JSON depending on type) that saves immediately via `workspace.getConfiguration().update(...)`, then Aggregated Stats, then the Providers table (moved from near the top to the bottom). The old "📋 Full Report (JSON)" dump and its copy-to-clipboard button were removed. Also fixes a bug where the panel always reported a hardcoded `extensionVersion: '0.1.0'` instead of the real installed version.
- **New: A/B Test Prompts across providers** - new **`AI Insights: A/B Test Prompts Across Providers`** command opens a panel where you pick one prompt and any number of provider/model variants (Claude Code CLI with model alias, GitHub Copilot via `vscode.lm` with any of its model list, or Codex CLI with a custom model id). Each selected variant runs the prompt headlessly in its own throwaway `git worktree` (branch `abtest/<variant>`) so nothing touches the real working copy, and the panel shows a results card per variant with the response, token usage, wall time, and any error. A "Open in New Window" button on each card opens that variant's worktree in a new VS Code window (`vscode.openFolder` with `forceNewWindow`) for further manual, hands-on comparison, and a "Clean up worktrees" button removes the temporary worktrees/branches once you're done. If the current workspace isn't a Git repository, the panel shows a warning instead of the config UI, since isolated worktrees require Git. Adds a new `CodexCliAdapter` (`codex exec --json`, best-effort JSONL token parsing with an estimated-token fallback) and a `model` parameter on the existing `ClaudeCodeCliAdapter` (`--model`) in `src/benchmark/adapters.ts`, reused by the new `src/abtest/` module (`types.ts`, `worktree.ts`, `runner.ts`) alongside the existing Technique Benchmark feature.
- **New: A/B Test added to the shared navigation bar** - "A/B Test" now appears alongside Dashboard, Repository, Sessions, etc. in every panel's top nav (`navShared.ts`'s `NAV_TABS`/`NAV_COMMANDS`), and the panel itself now renders the same shared topbar/pagebar as every other view instead of a bespoke header, so it's reachable and consistent from anywhere in the extension, not just the Command Palette.
- **New: each A/B Test result card shows three recap stats - tokens, code produced, and time** - "Code produced" is new: for the CLI-based variants (Claude Code, Codex), which have real file/tool access inside their worktree, it's a real `git diff --numstat` of lines added/deleted/files changed (worktree changes are staged with `git add -A` first so brand-new files count, not just edits to tracked ones). For the Copilot variant, which only calls `vscode.lm` and never touches the worktree's files, the diff is always empty, so instead the line count is estimated from fenced code blocks in the response text and labeled "estimated from response" so it isn't confused with a real diff.
- **Fix: A/B Test's GitHub Copilot variant had no way to see "the active file" / "this code" and could refuse the prompt outright** - `CopilotAdapter` is a bare `vscode.lm.sendRequest` call with no tools and no implicit editor context (unlike real Copilot Chat, which auto-attaches the open file), so a prompt phrased around ambient context reached the model with nothing to act on and it correctly declined (e.g. "I need the code first — I can't access your active VS Code file directly"). A new "Attach active editor as context" checkbox (on by default) in the A/B Test panel now snapshots the active editor's selection (or full document if nothing's selected) at run time and prepends it to the prompt sent to **every** variant, not just Copilot — this also makes the comparison fairer, since previously the CLI-based variants could poke around the worktree with their own tools while Copilot could not. The sidebar shows a live "Will attach `<file>` (N lines)" status that updates as you switch editors/selections.
- **New: A/B Test panel now surfaces GitHub Copilot's structural file-access limitation, and detects/cleans up worktrees orphaned by a previous session** - two follow-ups from a real report of a whole-project "find dead code" prompt getting an identical "no source file provided"-style refusal from every selected variant: (1) that report turned out to be several _GitHub Copilot_ model variants (Claude Sonnet 4.6, Gemini 3 Flash, GPT-5.3 Codex, all via `vscode.lm`) being asked a repo-wide question with no active file open — each one correctly declined, since none of them have any file/tool access beyond whatever's explicitly attached, unlike Claude Code/Codex CLI which can freely explore the whole worktree. Each provider group in the sidebar now shows a short note explaining this (Copilot: "no file/tool access beyond the attached context — use Claude Code or Codex for whole-project prompts"; CLI adapters: "full autonomous file access, but can take much longer"). (2) Investigating the report surfaced 5 real orphaned `abtest/*` worktrees/branches left over from an earlier session — "Clean up worktrees" only ever tracked the last run in memory (`AbTestViewProvider.lastResults`), so anything not cleaned up before the window closed/reloaded was silently stranded under the OS temp dir. New `listOrphanedAbTestWorktrees()` (`git worktree list --porcelain`, matched against the `abtest/` branch prefix) now runs on panel open and shows a "Found N leftover worktree(s) from a previous session — Clean up now" banner when it finds any.
- **New: A/B Test's GitHub Copilot variant can now explore its whole worktree via a bounded read-only tool loop, not just the attached active file** - new `CopilotAgentAdapter` (`src/abtest/copilotAgentAdapter.ts`) advertises three ad-hoc `vscode.lm` tools scoped to the variant's own worktree (`read_file`, `list_directory`, `search_files` — a plain-text/regex grep across source files, all sandboxed so a path can't escape the worktree root) and runs the standard tool-call loop (model requests a tool → adapter executes it locally → result fed back as a new message) for up to 8 round-trips before forcing a final answer. This is only used by A/B Test's `'copilot'` variant via `buildAbTestAdapter` in `runner.ts` — the plain `CopilotAdapter` used by Technique Benchmark is deliberately left tool-less, since that feature measures how different _injected_-context strategies perform in isolation, and giving it autonomous file access would let it bypass the context-starvation experiment entirely. `resolveCopilotModel` and `estimateTokens` were exported from `src/benchmark/adapters.ts` so the new adapter could reuse them instead of duplicating model-resolution logic.
- **Fix: A/B Test worktrees now live inside the project folder instead of the OS temp dir** - previously created under `os.tmpdir()/ai-abtest/<repoName>/<variantId>`; now under `<repoRoot>/.ai-abtest/<variantId>`, per explicit request to keep them visible/co-located with the project instead of buried in `/tmp` (also sidesteps any environment where the OS temp dir is restricted or on a different filesystem/mount than the repo, e.g. some WSL2 or locked-down corporate setups). Verified this doesn't pollute `git status` in the main repo: git already treats a nested worktree (it has its own `.git` file) as a repository boundary and won't descend into or report on it, and `setupAbTestWorktree` additionally writes a `/.ai-abtest/` entry to `.git/info/exclude` (local-only, never touches the tracked `.gitignore`) so the parent directory itself doesn't show as untracked before any worktree exists in it. VS Code's own Explorer/Search may still show these folders while a run is in progress, since they don't share git's nested-repo detection — only `git status`/`git add` are covered by this fix.
- **Fix: A/B Test's GitHub Copilot variant could finish with status "Done" but a completely empty response (0 output tokens, "0 files, estimated from response")** - the tool-call loop in `CopilotAgentAdapter` only ever kept the _last_ turn's text, so if the model's decisive turn (the one with zero further tool calls, or the forced final iteration) happened to contain only a tool call and no text, `responseText` was left as an empty string with no error - the run genuinely completed, it just had nothing to show, which read as "nothing happened." Fixed three ways: text is now accumulated across every turn as a fallback; if the tool-call budget (8 round-trips) runs out while the model still wants to call tools, one more request is made with tools omitted so it's forced to answer in plain text instead of trying to call another tool; and if the response is still empty after all of that, the adapter now throws a clear error ("`<model>` returned an empty response... — try a different model or rephrase the prompt") so the result card shows a real error state instead of a misleadingly blank "Done".
- **New: A/B Test's GitHub Copilot variant can now write/create files, not just read them** - `CopilotAgentAdapter` was deliberately read-only at first (read_file/list_directory/search_files only), which meant a prompt asking it to save or create something (e.g. "write a dead-code report to docs/dead_code.md") could only reply with something like "I cannot write files in this environment, but here is the content to save" instead of actually saving it. Added a fourth tool, `write_file` (path + content, creates parent directories as needed, capped at 200,000 chars), sandboxed through the same `resolveSafePath` check as the read-only tools so it can never write outside the worktree root. This also means the Copilot variant's "Code produced" stat can now be a real `git diff` (previously always the fenced-code-block estimate, since nothing was ever actually written) whenever it uses the new tool - verified with a live worktree test: a nested `docs/dead_code.md` created via the tool showed up correctly in `git diff --numstat` and a `../../etc/evil` escape attempt was rejected.
- **Fix: A/B Test's GitHub Copilot variant could exhaust its tool-call budget before ever reaching a planned `write_file` call** - `CopilotAgentAdapter`'s tool loop was capped at `MAX_TOOL_ITERATIONS = 8`, which a task that explores several files (`read_file`/`list_directory`/`search_files`) before writing could burn through entirely on exploration alone, especially since Copilot models tend to make one tool call per turn rather than batching several. When the budget ran out, the forced final answer correctly reported the truth ("Unable to write `dead.md` in this turn because tool calls are exhausted") instead of silently failing - but the underlying cap was simply too low for realistic explore-then-write tasks. Raised to 16.
- **Fix: raising the tool-call cap to 16 wasn't enough for a whole-repo "dead code" scan - still hit "tool calls are exhausted"** - rather than continuing to just raise a number that a sufficiently large/thorough exploration will always eventually exceed, made three complementary changes to `CopilotAgentAdapter`: (1) `MAX_TOOL_ITERATIONS` raised again, 16 → 24; (2) a new `buildFileTree()` helper lists every file in the worktree (capped at 300 entries) and includes it directly in the initial prompt, so the model no longer needs to spend early tool calls on `list_directory` just to discover the project's structure before it can start actually investigating - freeing up budget for real work; (3) when 3 tool calls remain, a message is now injected telling the model to stop exploring and use its remaining calls to finish (explicitly: call `write_file` now if one was planned) instead of continuing to read/search until the budget silently runs out.
- **New: A/B Test's GitHub Copilot variant can now handle whole-feature-generation-sized tasks** - two changes aimed at the stated goal of using A/B Test to generate whole features, not just small edits/reports, where `write_file`'s full-overwrite requirement gets expensive and risky for editing existing files, and the previous 24-call budget could still run out on a multi-file build: (1) new `edit_file` tool - a targeted search/replace (`{ path, old_text, new_text }`) for modifying part of an already-read existing file, mirroring the same "old text must match exactly and occur exactly once" semantics used by CLI coding agents' own edit tools, so the model doesn't have to reproduce an entire large file just to change a few lines; rejects with a clear error if `old_text` isn't found or isn't unique (asking for more surrounding context), so a bad match can't silently corrupt the file. (2) `MAX_TOOL_ITERATIONS` raised again, 24 → 50, specifically to give feature-sized (multiple new + edited files) tasks enough room. Verified live: a unique snippet replace, an ambiguous (non-unique) snippet correctly rejected, a non-existent snippet correctly rejected, and a path-escape attempt correctly rejected.
- **Fix: the "Enable Real Cache Data" button, warning, and dashboard nudge could all appear without GitHub Copilot Chat installed** - `dashboard.ts`, `pricingView.ts`, and the new insight rule only checked whether the setting read as off and whether the user had past Copilot usage, not whether `github.copilot-chat` is currently installed. A user who once used Copilot Chat but has since uninstalled it (data still present in history) would be told to turn on a setting belonging to an extension no longer on their machine. All three now also require `vscode.extensions.getExtension('github.copilot-chat')` to be present, matching the existing activation-prompt command's behavior.
- **New: dashboard-level nudge to enable real GitHub Copilot cache data** - the one-time activation prompt only ever fires once (by design, so it doesn't nag users who've dismissed or deliberately disabled it), which left no ongoing, visible indicator that Copilot cache numbers are estimated. A new insight rule (`copilot-real-cache-data-available`) now surfaces a 💡 tip on the main dashboard's AI Health card - dismissable/snoozable like every other insight - whenever the user has Copilot usage and `github.copilot.chat.agentDebugLog.fileLogging.enabled` is currently off, independent of whether the one-time popup was ever shown or dismissed. The tip now includes an actual "✅ Enable Real Cache Data" button inline (not just prose), so it's directly actionable from the main dashboard without needing to switch to the Copilot provider tab first.
- **Fix: no warning shown when GitHub Copilot's real-cache-data setting is turned off after being on** - the dashboard and Copilot credits page's Cache Efficiency widgets only showed the "Enable Real Cache Data" button in the "estimated" and "no data" states; the "measured, not calculated" state (shown whenever the current period's data happens to be all-real, e.g. from sessions logged before disabling the setting) never checked the _live_ setting value, so turning `github.copilot.chat.agentDebugLog.fileLogging.enabled` back off produced no visible acknowledgment or way to re-enable it - new sessions would silently fall back to estimates with no warning anywhere. Both widgets now show a ⚠️ notice + the enable button in the "measured" state too, whenever the live setting reads off.
- **Fix: Charts panel's blended Cache Hit Rate mislabeled real Copilot cache telemetry as "calculated"** - the "🧮 calculated, not measured" tooltip/icon on the summary tile and a new disclaimer on the Cache Efficiency chart tab were gated on `cacheReadTokens > 0` (true for both real and estimated data) instead of the `cacheTokensEstimated` flag, so genuinely measured cache numbers (from Copilot's opt-in debug-log telemetry) still showed the "calculated" disclaimer. This is the same class of bug fixed in `dashboard.ts`/`pricingView.ts` on 2026-07-04, which missed `charts.ts`. Now gated on `cacheTokensEstimated` like every other surface.
- **Fix: corrected stale doc/code/UI text claiming GitHub Copilot cache data "can't be accessed at all" or "isn't tracked"** - `applyCacheHeuristic()`'s doc comment in `copilot.ts`, `pricingView.ts`'s "How are Cache tokens calculated?" disclosure, and the dashboard's "About This Data" bullet (`dashboard.ts`) all predated the 2026-07-03 discovery that real cache data is available via Copilot's opt-in debug-log telemetry, and still stated the gap as unconditional/unfixable ("Cache Hit Rate / Cache Savings will read 0 for Copilot" was no longer true). Corrected all three to describe the heuristic as a fallback for when real data isn't available (no debug logging enabled, or session predates it); `pricingView.ts`'s disclosure now also branches on whether the current period's data is measured vs. estimated.
- **New: dashboard and Copilot credits page button to enable real GitHub Copilot cache data** - the Cache Efficiency widget's "calculated, not measured" and "no cache data" states now show an "✅ Enable Real Cache Data" button (visible only when the user has recent Copilot activity and hasn't already enabled it), instead of requiring the Command Palette or the one-time activation prompt to discover `AI Insights: Enable GitHub Copilot Real Cache Data`. Clicking it runs the same confirmation flow (Enable / Not now / Don't ask again, with the privacy note about local prompt/code logging) as the existing command - no setting is flipped without an explicit click.
- **Docs: documented the real-vs-estimated Copilot cache behavior before/after enabling debug logging**, and added the previously-missing comparison against `.others/ai-engineering-fluency`'s token/cache methodology (see `wiki/providers/copilot.md`) - confirms both projects rely on the same opt-in `github.copilot.chat.agentDebugLog.fileLogging.enabled` source for real Copilot cache data, with no alternate "real" source to port over.
- **Docs: analyzed and documented gaps in GitHub Copilot "AI Credits" reliability** (see `wiki/core/costEstimation.md`) - the credits figure is a token-cost-derived unit conversion, not GitHub's real premium-request-multiplier quota system; concretely, no multiplier accounting exists anywhere in the codebase, `debug-logs/{sessionId}/models.json`'s real per-model `billing.multiplier` data is discovered but never parsed, the real quota-consumed billing endpoint is never called, and the dashboard's "budget" is each plan's flat subscription price rather than its actual premium-request allowance value - documented as concrete follow-up items, not yet implemented.
- **New: Usage Health Score components now explain their own formula** - each component on the dashboard's AI Health card (Cache Efficiency, Context Quality, Cost Efficiency, Completion Acceptance, Budget Health) has a `<details>` disclosure under its current value showing the plain-language threshold behind the score (e.g. "Full 25 pts at ≥40% cache hit rate; scales down linearly to 0 pts at 0%"), so the scoring isn't a black box.
- **New: Context Anchoring tracking** - counts explicit context-reference tokens (`#file`, `#selection`, `#codebase`, `@workspace`, `@terminal`, etc.) found in prompts across all 6 providers, rolled up into a new "Context Anchoring" section on the Workspace Analysis page (total references, anchoring rate, per-type breakdown).
- **Fix: Antigravity sessions using the fallback token-estimation path could miscount which day their tokens belonged to** - when a session's log has no per-turn token counts (forcing a text-length-based turn estimate), every synthetic turn previously got the exact same timestamp (the file's mtime), so a session spanning several days had all of its tokens attributed to a single day in the dashboard's daily charts. Synthetic turns now interpolate evenly across the real timestamp span seen in the log when one is available.
- **New: Session Hygiene card** - dashboard section showing manual vs. automatic context-compaction counts, total tokens reclaimed by compaction, and how many sessions this period were flagged as "marathon" sessions (>80 turns or >3h), reusing the existing context-rot overload-signal thresholds rather than redefining them.
- **New: export the AI Health score as a PNG or copy it to the clipboard** - "📷 Save PNG" / "📋 Copy Image" buttons on the health-score card draw the grade, overall score, and per-component bars to an off-screen canvas client-side; no server round-trip and no new hosting - social-network posting was intentionally left out since there's no image hosting to support a real share-with-image flow.
- **New: rule-based insights replace the static recommendations list** - the health-score card's old 3-bullet static "Recommendations" list is now a 13-rule declarative catalog (tips, opportunities, and celebrations covering budget risk, spend spikes, cache efficiency, runaway sessions, acceptance rate, marathon sessions, compaction behavior, thinking overhead, tool-heavy sessions, context anchoring, and session depth), each dismissable or snoozable (1 week) via new ✕/💤 buttons that persist to a small JSON store (`insights-state.json` in global storage), mirroring the existing session-tags store.
- **GitHub Copilot: real cache/input/output tokens are now read from local telemetry, and current-version sessions are no longer missed entirely** - two bugs, found by re-checking an earlier (2026-07-02) conclusion that Copilot cache data was "confirmed unavailable": (1) `debug-logs/{sessionId}/main.jsonl` does contain real per-call `inputTokens`/`outputTokens`/`cachedTokens` telemetry (`llm_request` events) - the earlier check only looked at `debug-logs/main.jsonl` directly and never descended into the per-session subfolder, so it always found nothing; (2) Copilot Chat ≥ v0.55 stores sessions in a new `transcripts/{sessionId}.jsonl` typed-event format that discovery never scanned at all, meaning current-version sessions were invisible rather than merely estimated. `copilot.ts` now discovers `transcripts/`, parses its event schema, and correlates real telemetry from the matching debug log back onto every session format (by timestamp bucketing, since the two files share no common ID) - replacing the previous cache-token heuristic with measured data whenever a debug log is present, for any backend model.
- **GitHub Copilot: cache-read/cache-write tokens are estimated as a fallback when no real telemetry is available** - the turn-over-turn prompt-token diffing heuristic from earlier today (a turn's growth beyond its predecessor's full context treated as fresh/cache-write, everything below that as reused/cache-read) is now only used when the real-data path above finds no matching debug log. This remains the primary path for most Copilot users: the real-data source requires the opt-in, off-by-default `github.copilot.chat.agentDebugLog.fileLogging.enabled` VS Code setting, so anyone who hasn't explicitly turned it on gets no debug-log telemetry at all. Every UI surface showing Copilot cache numbers (dashboard Cache Efficiency widget, session detail view, replay view, session compare, pricing view) still marks these as "(calc.)" / "calculated, not measured" when the fallback applies. Settings unchanged: `aiInsights.providers.copilot.cacheEstimation.enabled` (default `true`) and `aiInsights.providers.copilot.cacheEstimation.convention` (`inclusive` default, or `exclusive`).
- **GitHub Copilot: `transcripts/` fallback token estimate now counts tool-call payloads, not just reply text** - `assistant.message.toolRequests[].arguments` (the model's own generated `apply_patch` diff, `create_file` body, terminal command, etc.) is real assistant output but was being silently dropped from the text-length estimate used when no real debug-log telemetry matches a turn. One real session's estimated output went from 824 to 7,386 tokens once these payloads were counted - tool-call arguments can dwarf the visible reply. Tool _results_ remain uncounted since Copilot's transcript format doesn't record them at all (`tool.execution_complete` only has `{toolCallId, success}`).
- **New: AI Insights offers to turn on GitHub Copilot's real cache-data telemetry for you** - since the previous entries' real-data path only activates when GitHub Copilot's own `github.copilot.chat.agentDebugLog.fileLogging.enabled` setting is on (off by default, and most users never touch it), a one-time activation prompt now asks whether to enable it, with **Enable / Not now / Don't ask again**. The prompt is explicit that enabling it makes Copilot write full prompts and code context to local per-session debug-log files that don't otherwise exist - it's a real data-handling change, not just a number-accuracy toggle, so it's never flipped silently. New command **`AI Insights: Enable GitHub Copilot Real Cache Data`** re-triggers it anytime (e.g. after dismissing), and new setting `aiInsights.providers.copilot.promptToEnableRealCacheData` (default `true`) turns the automatic prompt off entirely. Documented in the README under "GitHub Copilot: Real Cache/Token Data", replacing the old "not possible" framing with "real when this setting is on, calculated otherwise."
- **Fix: dashboard and pricing views mislabeled real Copilot cache telemetry as "(calc.)"** - `dashboard.ts`'s Cache Efficiency widget and `pricingView.ts`'s usage tables tagged cache numbers as "calculated, not measured" purely because `cacheReadTokens`/`cacheWriteTokens` were non-zero, without checking whether that data actually came from the heuristic or from real debug-log telemetry. Once real telemetry started flowing in (see entries above), this meant genuinely measured numbers still showed the "(calc.)" disclaimer. `ProviderMetrics` now carries an aggregate `cacheTokensEstimated` flag (true if any contributing session used the heuristic), computed in `sessionAggregator.ts` from each `Session.cacheTokensEstimated`; both views now gate their "(calc.)" tags and disclaimers on that flag instead of on token count alone, and the dashboard widget shows a "measured via Copilot telemetry" / "✅ Real cache/token counts" label when nothing in the period was estimated.
- **Docs: corrected the `transcripts/` format's minimum version claim, and explained why many sessions show no cache estimate** - the earlier "`transcripts/` format ≥ v0.55" note was a sample-of-one guess; checking every local `transcripts/{sessionId}.jsonl`'s own `copilotVersion`/`vscodeVersion` fields shows the format was already active at Copilot Chat `0.46.0` / VS Code `1.118.0` back on 2026-05-01 (earliest file retained; true origin unknown). Also documented, as expected behavior, that single-turn sessions can never get a cache estimate (the heuristic needs a previous turn to diff against) - most Copilot sessions on a typical machine turn out to be single-turn.
- **Fix: real GitHub Copilot cache/token telemetry was silently discarded for the top-level `chatSessions` format, worst of all on Remote-WSL/SSH/Codespaces** - `readDebugLogEvents()`'s path derivation only ever matched `transcripts/{sessionId}.jsonl` correctly; the top-level `workspaceRoot/chatSessions/{sessionId}.ext` VS Code actually writes sits one directory higher than the extension folder, so its derived debug-log path never existed, on any machine. On Remote-WSL specifically this was worse: `chatSessions` (client-side) and `transcripts`/`debug-logs` (remote-host-side) live on different filesystems under the same workspace hash, so the same conversation got parsed twice, and `dedupeSessions()`'s "pick the larger `totalTokens`" tiebreak favored the always-heuristic `chatSessions` copy over the real-telemetry `transcripts` copy in most cases - verified across 7 real duplicate sessions on a WSL2 machine before the fix, silently discarding real cache numbers 6 times out of 7. New `findDebugLogPath()` now falls back to searching every discovered `workspaceStorage` root for the same workspace-hash folder when the cheap same-directory derivation misses, fixing correlation for `chatSessions` universally and bridging the Remote-WSL/SSH client/remote-host split as a side effect. Verified against real local data: a previously heuristic-only session now correctly shows real telemetry (`76,288` / `45,824` / `36,480` cache-read tokens, matching its `transcripts` counterpart exactly) for every turn its debug log covers, with the heuristic still filling in the rest.

## [0.1.11] - 2026-07-01

- **Dashboard: Activity Heatmap distinguishes "not analyzed" from "zero activity"** - the heatmap always spans a trailing 371-day grid, but `daily` only contains data back to `aiInsights.sessionLookbackDays` (30 by default) since older sessions are never scanned. Previously both cases rendered as the same empty gray, making most of the year look like a wall of "no activity" when really it just hadn't been scanned. Dates before the lookback cutoff now render in a much dimmer, near-invisible gray (`rgba(255,255,255,0.03)`) with a tooltip explaining they're outside the analyzed window and pointing at the dropdown to widen it; dates within the window keep the normal 5-shade scale, including true zero-activity days.

- **Fix: Activity Heatmap grid overflowed its card by a few pixels** - `1fr` grid tracks are shorthand for `minmax(auto, 1fr)`, and the `aspect-ratio:1` day cells' content-derived automatic minimum could push the summed column widths past the container by a couple of pixels. Changed the week columns to `minmax(0, 1fr)` (so tracks can shrink to fit exactly) and added `overflow:hidden` on the grid as a safety net.

- **Dashboard: Activity Heatmap stretches to full width + shows a loading overlay while rescanning** - the heatmap grid is now a single CSS Grid (`28px` day-label column + one `1fr` column per week) instead of a fixed-pixel flex layout, so it fills the full width of its section instead of leaving a large empty gap on wide dashboards; each day cell uses `aspect-ratio:1` so it stays square as columns stretch/shrink with the panel width. Also, changing the "Analyzing last N days" dropdown now immediately shows the existing full-screen nav loading overlay ("Rescanning N days of session history…") before the extension re-scans session files and reloads the dashboard, instead of leaving the page looking frozen for the few seconds that takes.

- **Fix: dashboard JS error broke the period selector, dynamic cards/tables, and share panel** - the "Usage by Provider" cache-tooltip string in `dashboard.ts` (`updateProviderTable`) was written with `\'`-escaped apostrophes (`provider\'s`, `don\'t`, `can\'t`), but that JS lives inside the outer HTML **template literal**, so `\'` collapsed to a bare `'` in the emitted browser script - prematurely closing the single-quoted string and throwing a `SyntaxError` that aborted the _entire_ inline `<script>`.
